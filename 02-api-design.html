一、接口规范总则 Convention

基础路径
/api
版本策略 (URL 前缀)
/api/v1
请求格式
Content-Type: application/json
鉴权方式
Bearer Token (JWT)
分页参数
pageNum + pageSize
时间格式
ISO 8601

版本策略说明

所有接口路径以 /api/v1 为前缀，当前仅维护 v1 版本。当出现不兼容的接口变更时，将启用新版本前缀（如 /api/v2），旧版本至少保留 6 个月的过渡期。

鉴权说明

需要鉴权的接口，在请求头中携带 JWT Token：

HTTP Header
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMDAwMSIs...

分页约定

参数类型默认值说明
pageNumInteger1页码，从 1 开始
pageSizeInteger10每页条数，默认 10，最大 50

分页响应中包含：total（总记录数）、list（数据列表）、pageNum、pageSize、pages（总页数）。

时间格式

所有时间字段采用 ISO 8601 格式：yyyy-MM-dd'T'HH:mm:ss，示例：2026-07-29T10:00:00。时区默认为 Asia/Shanghai (UTC+8)。

二、统一响应格式 Response

2.1 标准响应

所有接口统一返回以下 JSON 结构：

JSON
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": "2026-07-29T10:00:00"
}
字段类型说明
codeInteger业务状态码，200 表示成功，非 200 为具体错误码
messageString状态描述信息
dataObject/null业务数据，失败时可能为 null
timestampString服务端响应时间戳（ISO 8601）

2.2 分页响应

分页查询接口的 data 字段结构：

JSON
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [ ... ],
    "total": 100,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 10
  },
  "timestamp": "2026-07-29T10:00:00"
}
字段类型说明
listArray当前页数据列表
totalLong总记录数
pageNumInteger当前页码
pageSizeInteger每页条数
pagesInteger总页数

2.3 错误响应示例

JSON - 参数校验失败
{
  "code": 400,
  "message": "参数校验失败：手机号格式不正确",
  "data": null,
  "timestamp": "2026-07-29T10:00:00"
}
JSON - 业务错误
{
  "code": 2003,
  "message": "库存不足，商品已售罄",
  "data": null,
  "timestamp": "2026-07-29T10:00:00"
}

三、统一错误码规范 Error Codes

错误码采用分段设计，四位数字编码，按模块划分，便于前端快速定位问题来源。

通用错误码 (0xxx)
错误码HTTP 状态说明处理建议
200200请求成功-
400400请求参数错误检查请求参数格式和必填项
401401未认证 / Token 过期跳转登录页或刷新 Token
403403无权限访问该资源确认用户角色权限
404404请求的资源不存在检查请求路径
405405请求方法不允许检查 HTTP Method
429429请求过于频繁，触发限流稍后重试
500500服务器内部异常联系管理员或稍后重试
用户模块错误码 (1xxx)
错误码说明触发场景
1001用户名已存在注册时用户名重复
1002手机号已注册注册时手机号已被使用
1003密码错误登录或修改密码时原密码不正确
1004账号已被禁用被管理员禁用的账号尝试登录
1005验证码错误或已过期图形验证码 / 短信验证码校验失败
1006旧密码不正确修改密码时旧密码验证失败
1007Token 刷新失败Refresh Token 已过期或无效
秒杀模块错误码 (2xxx)
错误码说明触发场景
2001秒杀活动不存在活动 ID 无效或已被删除
2002秒杀活动尚未开始当前时间早于活动开始时间
2003库存不足，商品已售罄Redis 预减库存判定为 0
2004重复下单，每位用户限购一次同一用户对同一秒杀商品重复下单
2005请求过于频繁，请稍后重试触发接口限流 / 验证码校验频率限制
2006秒杀活动已结束当前时间晚于活动结束时间
2007验证码未获取或已失效秒杀前未请求验证码或验证码超时
订单模块错误码 (3xxx)
错误码说明触发场景
3001订单不存在订单 ID 无效或无权查看
3002订单已支付，请勿重复操作对已支付订单再次支付
3003订单已取消对已取消的订单进行操作
3004订单支付超时，已自动取消超过 15 分钟未完成支付
3005支付处理失败支付接口调用异常
3006订单状态异常，无法操作订单处于不可操作的状态

4秒杀下单模块4 个接口
核心流程说明秒杀下单采用 "验证码前置 + Redis 预减库存 + RabbitMQ 异步下单" 架构。用户先获取验证码，校验通过后执行秒杀；服务端在 Redis 中原子预减库存，成功后将请求投递消息队列异步创建订单，前端通过轮询获取秒杀结果。

POST /api/v1/seckill/{seckillId} 执行秒杀（核心接口）
Bearer Token

请求参数

参数位置类型必填说明
seckillIdPathLong是秒杀活动 ID
seckillTokenBodyString是验证码校验后返回的秒杀令牌

响应数据

JSON - 排队中
{
  "code": 200,
  "message": "秒杀请求已提交，排队中",
  "data": {
    "seckillId": 5001,
    "requestId": "sk_req_5001_10001_7f3a",
    "status": 0,
    "statusText": "排队中"
  }
}
返回 requestId 后，前端通过轮询 /api/v1/seckill/{seckillId}/result 获取最终结果。
GET /api/v1/seckill/{seckillId}/result 查询秒杀结果（轮询）
Bearer Token

请求参数 (Query)

参数类型必填说明
seckillIdLong是秒杀活动 ID（Path）
requestIdString是执行秒杀返回的请求 ID（Query）

响应数据

JSON - 秒杀成功
{
  "code": 200,
  "data": {
    "status": 1,
    "statusText": "秒杀成功",
    "orderId": 80001,
    "payExpireTime": "2026-08-01T10:47:15"
  }
}
JSON - 秒杀失败
{
  "code": 200,
  "data": {
    "status": -1,
    "statusText": "秒杀失败: 库存不足",
    "orderId": null
  }
}
轮询策略status: 0=排队中（继续轮询），1=秒杀成功，-1=秒杀失败。建议轮询间隔：前 5 次每 1 秒，之后每 2 秒，最多轮询 30 次。

前端轮询伪代码

JavaScript
async function pollSeckillResult(seckillId, requestId) {
  let attempts = 0;
  const maxAttempts = 30;

  while (attempts < maxAttempts) {
    const delay = attempts < 5 ? 1000 : 2000;
    await sleep(delay);

    const res = await fetch(
      `/api/v1/seckill/${seckillId}/result?requestId=${requestId}`
    );
    const { data } = await res.json();

    if (data.status === 1) {
      // 秒杀成功，跳转支付页
      router.push(`/order/pay/${data.orderId}`);
      return;
    }
    if (data.status === -1) {
      // 秒杀失败，显示失败提示
      showToast(data.statusText);
      return;
    }
    // status === 0，继续轮询
    attempts++;
  }
  // 超时处理
  showToast('处理超时，请在"我的订单"中查看');
}
