# 秒杀商城系统 — 前后端全链路业务流程图文档

> **版本**: v1.0  
> **生成日期**: 2026-08-05  
> **覆盖范围**: 用户认证、商品与分类、订单与钱包三大模块全部业务场景  
> **分析深度**: 前端组件 → API调用 → 后端Controller → Service → Mapper → 中间件交互 → 数据封装返回（方法调用级别）

---

## 一、文档概述

本文档对秒杀商城系统的全部核心业务场景进行前后端全链路分析，每个场景按以下 **四层结构** 逐层剖析：

| 层次 | 说明 |
|------|------|
| **① 前端执行流程** | Vue组件交互 → Pinia Store → API封装函数 → HTTP请求 |
| **② 后端执行流程** | Controller → Service → Mapper → 业务逻辑（事务、校验、加密等） |
| **③ 中间件与数据存储交互** | Redis读写策略、MySQL事务操作、RabbitMQ消息投递、文件系统写入 |
| **④ 数据流转机制** | 请求/响应VO封装、缓存穿透/击穿/雪崩防护、分布式锁、原子操作、异步回调 |

每个场景均配有 **Mermaid时序图**，直观展示各组件间的调用时序与数据流向。

### 3.1 用户登录

#### 3.1.1 前端执行流程

| 步骤 | 组件/方法 | 说明 |
|------|-----------|------|
| 1 | `Login.vue` | 用户输入用户名、密码，可选输入图形验证码 |
| 2 | `handleLogin()` | 表单校验（非空、格式） |
| 3 | `userStore.login()` | 调用Pinia Store的login action |
| 4 | `authApi.login()` | 封装HTTP请求 |
| 5 | `POST /api/v1/auth/login` | 发送登录请求（含username、password、captchaUuid、captchaCode） |
| 6 | 成功响应 | Token存入localStorage + Pinia state，跳转首页 |
| 7 | 失败响应 | 显示错误信息，失败3次后强制要求验证码 |

#### 3.1.2 后端执行流程

| 步骤 | 方法 | 说明 |
|------|------|------|
| 1 | `AuthController.login()` | 接收LoginDTO，参数校验 |
| 2 | `AuthServiceImpl.login()` | 核心登录逻辑 |
| 3 | `CaptchaService.verifyCaptcha()` | 验证码校验（3次失败后必填） |
| 4 | `Redis GET login:fail:{username}` | 查询失败计数 |
| 5 | `UserMapper.findByUsername()` | 查询用户记录 |
| 6 | `passwordEncoder.matches()` | BCrypt密码比对 |
| 7 | 失败计数检查 | ≥5次锁定30分钟，≥3次强制验证码 |
| 8 | `JwtUtils.generateToken()` | RS256算法签发JWT |
| 9 | `TokenVersionService.getVersion()` | 获取用户Token版本号 |
| 10 | `UserStatusCacheService.warmUp()` | 预热用户状态缓存 |
| 11 | `LoginVO` 封装返回 | accessToken + userInfo |

#### 3.1.3 中间件与数据存储交互

| 中间件 | Key/操作 | 说明 |
|--------|----------|------|
| Redis | `login:fail:{username}` | 失败计数，30min TTL，登录成功则删除 |
| Redis | `captcha:{uuid}` | 图形验证码，5min TTL，验证后删除 |
| Redis | `user:token-version:{userId}` | Token版本号，30天TTL |
| Redis | `user:auth:{userId}` | 用户状态缓存，60s TTL |
| MySQL | `t_user` SELECT | 根据username查询 |
| MySQL | `t_login_log` INSERT | 记录登录日志 |

#### 3.1.4 数据流转机制

- **请求流**: LoginDTO(username, password, captchaUuid, captchaCode) → Controller → Service
- **安全流**: 失败计数Redis检查 → BCrypt校验 → 锁定判定 → JWT签发
- **响应流**: LoginVO(accessToken, userId, username, role, avatarUrl) → 前端存储
- **缓存预热**: 登录成功后写入user:auth缓存，后续请求优先走缓存

#### 3.1.5 Mermaid时序图

```mermaid
sequenceDiagram
    participant U as 用户
    participant V as Login.vue
    participant Store as userStore(Pinia)
    participant API as authApi
    participant Ctrl as AuthController
    participant Svc as AuthServiceImpl
    participant Captcha as CaptchaService
    participant Redis as Redis
    participant Mapper as UserMapper
    participant JWT as JwtUtils
    participant TV as TokenVersionService
    participant USC as UserStatusCacheService
    participant DB as MySQL

    U->>V: 输入用户名/密码/验证码
    V->>V: handleLogin() 表单校验
    V->>Store: login(username, password, captcha)
    Store->>API: authApi.login()
    API->>Ctrl: POST /api/v1/auth/login

    Ctrl->>Svc: login(LoginDTO)
    Svc->>Redis: GET login:fail:{username}
    alt 失败次数≥3
        Svc->>Captcha: verifyCaptcha(uuid, code)
        Captcha->>Redis: GET captcha:{uuid} + DEL
    end
    Svc->>Mapper: findByUsername(username)
    Mapper->>DB: SELECT FROM t_user
    DB-->>Mapper: User实体
    Mapper-->>Svc: User

    Svc->>Svc: passwordEncoder.matches(raw, encoded)
    alt 密码错误
        Svc->>Redis: INCR login:fail:{username} (TTL 30min)
        alt 失败次数≥5
            Svc-->>Ctrl: 账号锁定30分钟
        else 失败次数≥3
            Svc-->>Ctrl: 需要验证码
        end
    else 密码正确
        Svc->>Redis: DEL login:fail:{username}
        Svc->>JWT: generateToken(userId, role)
        JWT-->>Svc: accessToken
        Svc->>TV: getVersion(userId)
        TV->>Redis: GET user:token-version:{userId}
        TV-->>Svc: version
        Svc->>USC: warmUp(userId, status)
        USC->>Redis: SET user:auth:{userId} (TTL 60s)
        Svc-->>Ctrl: LoginVO
        Ctrl-->>API: 200 + LoginVO
        API-->>Store: 存储Token + userInfo
        Store-->>V: 登录成功
        V->>U: 跳转首页
    end
```

### 3.3 密码修改

#### 3.3.1 前端执行流程

| 步骤 | 组件/方法 | 说明 |
|------|-----------|------|
| 1 | `UserProfile.vue` | 用户输入旧密码、新密码、确认密码 |
| 2 | `handleChangePassword()` | 表单校验（新旧密码不同、确认一致） |
| 3 | `changePassword()` | 调用密码修改API |
| 4 | `PUT /api/v1/auth/password` | 发送修改请求（需JWT认证） |
| 5 | 修改成功 | 退出登录，跳转/login |

#### 3.3.2 后端执行流程

| 步骤 | 方法 | 说明 |
|------|------|------|
| 1 | `AuthController.changePassword()` | 接收ChangePasswordDTO |
| 2 | `AuthServiceImpl.changePassword()` | @Transactional事务 |
| 3 | `passwordEncoder.matches()` | 旧密码校验 |
| 4 | `passwordEncoder.encode()` | 新密码加密 |
| 5 | `UserMapper.updateById()` | 更新密码 |
| 6 | `TokenVersionService.incrementVersion()` | 版本号递增，踢所有设备 |
| 7 | `UserStatusCacheService.invalidateUserAuth()` | 删除用户状态缓存 |

#### 3.3.3 中间件与数据存储交互

| 中间件 | Key/操作 | 说明 |
|--------|----------|------|
| Redis | `user:token-version:{userId}` | INCR递增，使所有旧Token失效 |
| Redis | `user:auth:{userId}` | DEL删除，下次请求重新从DB加载 |
| MySQL | `t_user` UPDATE | 更新password字段 |

#### 3.3.4 数据流转机制

- **请求流**: ChangePasswordDTO(oldPassword, newPassword) → Controller → Service
- **安全流**: 旧密码BCrypt校验 → 新密码加密 → 版本号递增（踢所有设备） → 缓存失效
- **响应流**: 成功后前端主动logout，清除本地Token，跳转登录页

### 3.4 找回密码

#### 3.4.1 前端执行流程

| 步骤 | 组件/方法 | 说明 |
|------|-----------|------|
| 1 | `ForgotPassword.vue` | 两步流程：发送验证码 → 重置密码 |
| 2 | `sendForgotPasswordCode()` | `POST /api/v1/auth/forgot-password/send-code` |
| 3 | `resetPassword()` | `POST /api/v1/auth/forgot-password/reset` |
| 4 | 重置成功 | 跳转/login |

#### 3.4.2 后端执行流程

| 步骤 | 方法 | 说明 |
|------|------|------|
| 1 | `AuthServiceImpl.sendForgotPasswordCode()` | 查找用户 → 发送短信/邮件验证码 |
| 2 | `findUserByAccount()` | 根据账号查找用户 |
| 3 | `VerificationCodeServiceImpl.sendSmsCode/sendEmailCode()` | 发送验证码 |
| 4 | Redis标记Key | `forgot-password:{type}:{account}` 防止重复发送 |
| 5 | `AuthServiceImpl.resetPassword()` | @Transactional事务 |
| 6 | 标记Key校验 | 验证是否经过发送验证码步骤 |
| 7 | `verifyCode()` | 验证码校验 |
| 8 | `passwordEncoder.encode()` | 新密码加密 |
| 9 | `updateById()` | 更新密码 |
| 10 | `incrementVersion()` | 踢所有设备 |

#### 3.4.3 中间件与数据存储交互

| 中间件 | Key/操作 | 说明 |
|--------|----------|------|
| Redis | `verify_code:{account}` | 验证码，5min TTL |
| Redis | `verify_code:rate:{account}` | 发送频率限制，60s TTL |
| Redis | `forgot-password:{type}:{account}` | 标记Key，5min TTL，防止未验证直接重置 |
| Redis | `user:token-version:{userId}` | INCR递增 |
| MySQL | `t_user` SELECT + UPDATE | 查找用户 + 更新密码 |

#### 3.4.4 数据流转机制

- **第一步流**: account → findUserByAccount → sendCode → Redis存储验证码+标记Key
- **第二步流**: account+code+newPassword → 标记Key校验 → 验证码校验 → 密码加密 → 更新DB → 版本号递增
- **安全机制**: 标记Key确保必须先发送验证码才能重置，频率限制防刷

| 3 | `order.cancel.queue` | 死信路由到取消队列 |
| 4 | `OrderCancelConsumer` | 消费取消消息 |
| 5 | `timeoutCancel()` | 执行超时取消逻辑 |

#### 3.17.4 中间件与数据存储交互

| 中间件 | Key/操作 | 说明 |
|--------|----------|------|
| Redis | `seckill:stock:{goodsId}` | INCR库存回补 |
| Redis | `seckill:bought:{goodsId}` | SREM移除已购标记 |
| RabbitMQ | `order.delay.queue` | 延迟队列(TTL=15min) |
| RabbitMQ | DLX → `order.cancel.queue` | 死信路由 |
| MySQL | `t_seckill_order` UPDATE | 状态置CANCELLED |

#### 3.17.5 数据流转机制

- **主动取消**: 用户操作 → 状态校验 → 更新DB → 事务提交后Redis回补
- **超时取消**: 延迟队列(15min) → DLX → 取消消费者 → timeoutCancel() → Redis回补
- **事务后回调**: `registerAfterCommit()` 确保DB事务提交成功后才回补Redis，避免数据不一致
