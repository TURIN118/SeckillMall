## 一、Vite代理模式改造

- **目标**：将项目从"跨域直连后端"模式改造为"Vite代理转发"模式，同时修复后端 CORS 遗漏问题（关联秒杀抢购 401 修复）。
- **要点**：
  1. 将 `VITE_API_BASE_URL` 从绝对 URL 改为空值，使请求变为相对路径走 Vite 代理（同源，免 CORS）。
  2. 增强 `vite.config.ts` 代理配置：新增 `VITE_PROXY_TARGET` 变量、`ws:true`（支持 WebSocket）、`secure:false`，并扩展 `/images`、`/upload` 代理。
  3. 修复 `request.ts` 中 Token 刷新请求的 URL 拼接逻辑，避免 baseURL 改空后拼接异常。
  4. 后端 `ReplayProtectionFilter` 的 reject() 响应补充 CORS 头，避免秒杀重放拒绝时跨域失败。
  5. 签名实现采用 Web Crypto API（浏览器原生，零依赖，异步非阻塞）。
- **核心文件**：
  - `frontend/.env.development`、`frontend/vite.config.ts`、`frontend/src/api/request.ts`
  - `seckill-mall/.../SecurityConfig.java`、`ReplayProtectionFilter.java`

## 二、JWT无状态服务优化

- **目标**：解决当前每个鉴权请求都查数据库的性能瓶颈，引入 Redis 缓存用户状态，提升秒杀高并发场景下的鉴权性能（万级 QPS 下 DB 压力降低 98%）。
- **要点**：
  1. 引入 Redis 缓存用户状态：Key `user:auth:{userId}`，Hash 结构，TTL 60 秒，字段含 status/role/username/nickname。
  2. 新增 `UserStatusCacheService` 封装缓存读写逻辑，Filter 鉴权时先查 Redis 未命中再查 DB 并回填。
  3. 三种缓存写入情境：Filter 鉴权未命中回填、登录成功主动预热、管理员修改用户状态时主动刷新。
  4. 状态变更通过"主动删除缓存"实现秒级生效，TTL 仅作兜底（防忘记主动删）。
  5. 保留现有 Token 黑名单机制（Redis `token:blacklist:{jti}`，Fail-Closed 策略）与 Refresh Token 一次性轮换。
- **核心文件**：
  - 新增 `security/UserStatusCacheService.java`
  - `JwtAuthenticationFilter.java`、`AuthServiceImpl.java`、`AdminUserServiceImpl.java`
  - `TokenBlacklistService.java`、`application-dev.yml`

## 三、发货功能改进

- **目标**：当前发货流程仅改状态无物流信息（不可用），改进为支持填写快递公司+快递单号的完整发货流程，并支持用户确认收货。
- **要点**：
  1. `t_seckill_order` 与 `t_normal_order` 新增 4 个物流字段：`shipping_company`、`shipping_no`、`ship_time`、`confirm_time`。
  2. 订单状态枚举增加 `SHIPPED`（已发货），完整流转：UNPAID→PAID→SHIPPED→COMPLETED。
  3. 新增 `ShipRequest` DTO，校验物流公司（≤50字符）与快递单号（≤64字符）非空。
  4. 发货接口 `POST /api/order/{id}/ship` 接收物流信息，需 ADMIN 权限并校验订单状态为 PAID。
  5. 新增确认收货接口 `POST /api/order/{id}/confirm`，校验订单归属与 SHIPPED 状态后置为 COMPLETED。
  6. 为快递单号创建索引 `idx_shipping_no` 便于用户查询。
- **核心文件**：
  - 实体：`SeckillOrder.java`、`NormalOrder.java`
  - DTO：`dto/ShipRequest.java`（新增）
  - 接口：`OrderController.java`
  - SQL：`db/migration_v6_shipping.sql`、`test/resources/schema-h2.sql`

## 四、SKU多规格商品系统

- **目标**：为 seckill-mall 引入完整 SKU 多规格商品系统，支持多维度规格定义、SKU 组合独立计价、全链路 SKU 信息传递，并保持对旧商品的向后兼容。
- **要点**：
  1. **数据模型**：新增 3 张表（`t_product_attribute` 属性表、`t_product_attribute_value` 属性值表、`t_product_sku` SKU 组合表），修改 3 张表（`t_cart`、`t_normal_order_item`、`t_product_review` 增加 sku_id 与 sku_attributes 快照）。
  2. **分类规格模板**：新增 `t_category_attribute` 与 `t_category_attribute_value`，在分类级固化规格维度模板，添加商品时自动带出，支持覆盖与扩展。
  3. **SKU 组合**：属性值笛卡尔积自动生成 SKU，每个 SKU 独立拥有 price/stock/main_image/sku_code/status。
  4. **全链路传递**：商品详情→加购/立即购买→购物车→订单明细→评论，整条链路携带并展示 SKU 信息（JSON 快照避免历史订单受后续修改影响）。
  5. **前端**：后台 `ProductEdit.vue` 增加规格配置区与 SKU 表格；前台 `ProductDetail.vue` SKU 选择器对接后端数据，价格/库存/主图随选择实时联动，禁用无库存组合。
  6. **向后兼容**：无 SKU 的旧商品继续以 `t_product.original_price`/`stock` 兜底，平滑过渡。
- **核心文件**：
  - 新增表：`t_product_attribute`、`t_product_attribute_value`、`t_product_sku`、`t_category_attribute`、`t_category_attribute_value`
  - 实体：`Product.java`、`Cart.java`、`NormalOrderItem.java`、`ProductReview.java`
  - 前端：`ProductEdit.vue`、`ProductDetail.vue`、`api/sku.ts`、`types/index.ts`
  - SQL：`schema.sql`、迁移脚本

## 五、商品添加字段说明

- **目标**：详细说明后台管理系统添加商品时各字段的填写规范、校验规则及注意事项，作为商品录入的操作参考。
- **要点**：
  1. **9 个核心录入字段**：商品名称（2~100字符）、商品分类（级联选择）、商品价格（≥0.01）、库存数量（≥0）、商品主图（单图）、商品图片（多图最多5张）、商品简介（≤500字符）、商品详情（富文本 HTML）、商品状态（ON_SALE/OFF_SHELF）。
  2. **前端控件与后端校验对应**：每个字段均明确前端控件类型（el-input/el-cascader/el-input-number/ImageUploader/wangEditor/el-radio-group）与后端校验注解（@NotBlank/@Size/@NotNull/@DecimalMin/@Min）。
  3. **图片合并存储机制**：前端 `mainImage` 与 `images` 提交时合并为一个 `images` 数组（主图作 images[0]），后端 `ProductServiceImpl` 保存时提取 images[0] 为 `main_image` 字段。
  4. **7 个自动填充字段**：id（雪花算法）、salesCount、cartCount、favoriteCount、isDeleted、createTime、updateTime 由系统自动维护，无需手动填写。
  5. **数据库字段映射**：明确前端表单字段 → 后端 DTO 字段 → 数据库字段 → 数据库类型的完整映射关系。
- **核心文件**：
  - 数据库表：`t_product`
  - DTO：`ProductCreateRequest.java`、`ProductUpdateRequest.java`
  - 前端：`frontend/src/views/admin/ProductEdit.vue`
  - 服务：`ProductServiceImpl.java`
  - API：`POST /api/v1/admin/products`
